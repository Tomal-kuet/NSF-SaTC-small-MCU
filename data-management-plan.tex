\section*{\large Data Management and Sharing Plan}

\vspace{4pt}

\noindent Our data management and sharing plan ensures that project data, software, and educational
materials are collected responsibly, documented clearly, and shared openly, while managing the
one real safety concern this project's outputs raise: working exploit code is dual-use until the
vulnerability it targets is patched.
Everything else --- the corpus, the benchmark once disclosed, the enforcement and attestation
prototypes, and the course material --- is released without restriction, since the goal stated
throughout the proposal is a benchmark and toolchain any RTOS maintainer can run independently
of us.

\head{Data and Software.}
The project produces three kinds of output.
\emph{Research data}: the exploitation-requirement dataset, a per-CVE record (category~(i)--(iv)
label, risky component and input, recurring code shape, critical variables) extracted from the
\nNetCVE{} network-component CVEs disclosed against \nRtos{} RTOSes~\cite{tan24sok}; the
cross-stack pattern-confirmation records from Task~1.1; the benchmark of reproduced exploits
(build configuration, triggering input sequence, oracle predicate, expected verdict) on both
physical boards and scoped rehosted targets from Task~1.3; and the security and cost measurements
from the RT~2/RT~3 evaluation (equivalent-target-set counts, throughput, latency, flash/RAM,
worst-case execution time, attestation report size, verifier latency).
Every record in this dataset is derived from an already-public CVE advisory, so none of it is
sensitive on its own.
The one exception is a confirmed cross-stack \emph{variant} of a known pattern before its
coordinated disclosure completes: that exploit is held privately, shared only with the affected
maintainer, and joins the public benchmark once a patch ships, exactly as the project description's
disclosure policy commits.
\emph{Software}: the LLVM instrumentation passes for protocol-state-aware control-flow and
critical-data-flow integrity (RT~2); the attestation compiler, analyzer and verifier extending the
open-source ENOLA toolchain~\cite{armanuzzaman2026enola} (RT~3); the cross-stack query tooling and
scoped-rehosting harness (RT~1); and the benchmark harness itself.
\emph{Educational materials}: the capture-the-flag challenges and hands-on lab modules built on the
benchmark, and course material for the new non-Linux embedded-systems-security course at UCCS and
UTEP.

\head{Standards and Formats.}
Source and instrumentation are C and LLVM IR, with Python for the analysis and query tooling.
Dataset records use CSV/JSON against a documented labeling schema, published alongside the data so
a reader does not have to reconstruct what a category or a critical-variable field means.
Benchmark cases carry pinned build manifests and container or emulator images so a rehosted target
reconstructs exactly, and the packet inputs that trigger each case are stored as PCAP.
Hardware measurements (trace captures, timing logs) are stored as CSV or the instrument's native
binary format alongside a script that parses it.
Documentation, including the Task~1.1 extraction decision procedure and inter-rater agreement
method, is Markdown and PDF.
Every record and every benchmark case carries provenance metadata: source CVE identifier, RTOS and
version, build configuration, and disclosure status, so reuse does not require guessing context.

\head{Access and Sharing.}
GitHub is the working repository for code, data and documentation; tagged releases are mirrored to
Zenodo with DOIs for long-term citability, and publications are deposited in NSF-PAR.
Material under an active coordinated-disclosure embargo is held privately until a patch ships, at
which point it is released with the rest of the benchmark; this is a temporary delay, not an
access restriction, and nothing in this project is withheld from any country or class of user once
disclosure completes.
If a specific artifact remains sensitive even after disclosure, that case is reviewed by the PIs in
consultation with the sponsored-research offices at UCCS and UTEP before release.

\head{Reuse and Redistribution.}
Software is released under a permissive license (MIT or BSD) and data and educational material
under Creative Commons, so the community can reuse, redistribute and build derivatives with
attribution.
Where a benchmark case carries modified upstream RTOS source, redistribution respects that
project's own license; we do not relicense third-party code, only the instrumentation, patches and
analysis artifacts layered on it.
The one thing never distributed is working exploit input for a vulnerability that is not yet
patched, for the reason stated above.
Version control and a public issue tracker on GitHub support responsible reuse and let other
groups extend the benchmark independently of us, which is the stated goal of releasing it.

\head{Archiving and Preservation.}
Data, code and documentation are retained for at least three years beyond the end of the award on
secured, backed-up servers at UCCS and UTEP under institutional IT policy, and mirrored
indefinitely on GitHub and Zenodo so persistence does not depend on either institution's retention
window alone.
Publications remain accessible through publisher repositories and NSF-PAR.

\head{Ethics and Responsible Disclosure.}
The project involves no human subjects and no personally identifiable information: every record is
a CVE advisory, source code, or a hardware or network measurement taken from equipment the team
owns, so IRB review is not required.
The applicable risk is dual-use, not privacy, and it is handled the same way throughout the
proposal: exploitation is performed only on hardware the team owns or in emulation, no third-party
or production device is targeted, and every confirmed variant enters coordinated disclosure with
the affected project before publication or public release.

\head{Prior Experience.}
Both PIs have a record of releasing research artifacts responsibly.
PI~Tan has open-sourced the CVE systematization this project extends~\cite{tan24sok} and prior
Cortex-M control-flow defense prototypes~\cite{ma2023dac,tan2023sherloc}.
Co-PI~Armanuzzaman has open-sourced ENOLA~\cite{armanuzzaman2026enola}, the control-flow
attestation system RT~3 builds on, with its implementation and evaluation publicly released.
Both PIs' capture-the-flag and course material has likewise been shared with the community they
teach and compete in.
